# Kafka Streams 100K benchmark — 4 partitions control

Purpose:
Additional control benchmark for Part 5.
The goal was to check whether the previous 6-partition / 4-pod Kafka Streams
task distribution was the main reason for the performance difference.

Workload:
- 100,000 order hierarchies
- 500,000 input messages
- 100,000 expected verification records
- 1,000 hierarchy warm-up before each measured run
- 3 measured runs

Kafka topics:
- org.example.order.executions: 4 partitions
- org.example.order.verification: 4 partitions
- replication factor: 1

Kafka Streams setup:
- Kubernetes
- 4 application pods
- num.stream.threads=1
- 4 active Kafka Streams tasks expected
- processing.guarantee=at_least_once
- commit.interval.ms=100
- local RocksDB state store
- Kafka changelog topics

JVM:
- Java 25

Acceptance criteria:
- all 100,000 verification records produced
- one accepted final completion record per hierarchy
- processor distribution expected to be close to 25k / 25k / 25k / 25k
