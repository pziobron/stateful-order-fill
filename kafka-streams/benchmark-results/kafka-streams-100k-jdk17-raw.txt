Notes:

* This control experiment repeats the Kafka Streams 100K benchmark with Java 17 instead of Java 25.
* The topology, partition count, application pod count, stream-thread count, commit interval, processing guarantee, resource limits, and benchmark procedure remained unchanged.
* Each measured run used fresh Kafka broker storage, fresh input and verification topics, fresh internal topics, and fresh Kafka Streams application state.
* Each measured run was preceded by exactly one 1,000-iteration warm-up.
* No additional 10K run was executed on the same processor state before the 100K measurement.
* Six partition tasks were assigned to four stream threads, producing the expected approximately 2:1 processor distribution.
* Runs were accepted only when no rebalance, restart, OOM, or uncaught processing error occurred during measurement.
* Median values are calculated from the three SCENARIO_RESULT lines below.
* The purpose of this run is to estimate whether the JVM-version difference materially affects the main Flink versus Kafka Streams comparison.
