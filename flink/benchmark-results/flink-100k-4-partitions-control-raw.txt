# Apache Flink 100K benchmark — 4 partitions control

Purpose:
Additional control benchmark for Part 5.
The goal was to check whether using the same number of Kafka partitions
and processing units changes the Flink vs Kafka Streams comparison.

Workload:
- 100,000 order hierarchies
- 500,000 input messages
- 100,000 expected verification records
- 1,000 hierarchy warm-up before each measured run
- 3 measured runs

Kafka topics:
- org.example.order.executions: 4 partitions
- org.example.order.verification: 4 partitions
- replication factor: 1

Flink setup:
- Kubernetes
- 4 TaskManagers
- 1 slot per TaskManager
- FLINK_PARALLELISM=4
- HashMapStateBackend
- filesystem checkpoint storage
- checkpoint interval: 10 seconds
- Kafka sink delivery guarantee: AT_LEAST_ONCE

Acceptance criteria:
- all 100,000 verification records produced
- one accepted final completion record per hierarchy
- successful processing under durable checkpoint configuration
